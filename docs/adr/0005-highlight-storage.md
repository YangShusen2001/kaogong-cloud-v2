# ADR 0005：用户划线采用版本化段落状态

- **状态**：已接受
- **日期**：2026-08-14

## 背景

旧实现由浏览器先删除一个段落的全部划线，再逐条创建新区间。网络失败、页面关闭或并发编辑会造成部分保存或永久数据丢失。D1 不应依赖浏览器发出的多次请求模拟事务。

## 决策

- 每个“用户 + 文章 + 段落”保存为一行 JSON 状态。
- 行包含 `version`、规范化 spans 和更新时间。
- 客户端替换段落时携带 `baseVersion`。
- 服务端通过单条带版本条件的 upsert 原子替换状态。
- 陈旧版本返回 `409 HIGHLIGHT_CONFLICT`，客户端重新加载。
- 删除保存为空 spans 的新版本 tombstone，不删除段落行。旧客户端、旧版本或并发删除不能使已删除划线复活。
- 旧单条划线接口暂时保留，只用于读取和过渡；新阅读页只写版本化段落状态。

## 旧数据策略

当前没有真实生产用户。旧版无段落偏移的数据无法可靠恢复位置，因此不猜测或伪造位置：

- 已有有效 `styles/start/end` 的单条记录可作为首次加载回退数据，但版本化 tombstone 优先压制同段较旧记录。
- 若旧单条记录晚于版本化状态，可按更新时间显示并在下一次写入时收敛；时间相同时版本化状态获胜。
- 零长度或空样式记录不渲染。
- 正式上线前本地和预览 D1 可以重建。
- 一旦存在真实用户，禁止再使用重建策略，后续迁移必须提供可验证回填或人工恢复报告。

## 后果

- 一次保存不会出现“删除成功、创建部分失败”。
- 多标签页编辑可以识别冲突。
- 空段落状态会持续占用一行，这是防止旧数据复活所需的删除证据。
- 需要维护段落 JSON 契约和浏览器回归测试。
- AI 标注仍是独立只读内容数据，不进入该表。
