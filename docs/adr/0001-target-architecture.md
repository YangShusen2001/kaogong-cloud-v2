# ADR 0001：目标架构（现代化迁移）

- **状态**：已接受
- **日期**：2026-08-13
- **决策者**：用户（拍板）+ 架构师（教学式引导）

## 背景

原项目 `kaogong-cloud` 是一个能跑的个人学习站（Python 零依赖管线 + 手写原生 JS + Cloudflare Pages/Workers/KV）。它的问题不是"乱"，而是：

1. 没有构建工具，资产版本靠手写升号（`style-v29.css`）；
2. 契约靠文档人肉对齐，导致同一事实多处漂移（更新时间的 07:00 / 07:10 / 01:00 三种说法）；
3. 手搓 HTTP/markdown 解析器等（零第三方依赖哲学）；
4. 文档/流程过载（43 个任务提案、loss log、多 Agent 仪式感）。

## 决策

**保留「定时抓取 → 静态站 → Serverless」的架构形状，把每一层的手搓实现替换为工业标准工具；在 D 盘全新绿场重构，原项目只作参考，最后整体切换。**

## 目标架构

```
kaogong-cloud-v2/
├── apps/
│   ├── web/        Astro + TypeScript 静态站（可独立部署）
│   └── api/        Cloudflare Worker：Hono + Drizzle + D1（可独立部署）
├── packages/
│   └── contracts/  前后端 + 管道共享的类型契约（唯一事实源）
├── content/        管道产出的结构化内容（Astro content collection 消费）
├── pipeline/       Python ETL（抓取→生成），uv + pytest 标准化
├── docs/adr/       架构决策记录
└── .github/        标准化 CI
```

### 关键设计点

1. **关注点分离**：`apps/web` 与 `apps/api` 是两个可独立构建、独立部署、独立回滚的单元。
2. **契约单源**：API 返回什么字段、内容文件什么结构，由 `packages/contracts` 一份类型定义；前端、后端、管道都从这里 import，一处改动全项目编译期对齐，物理上杜绝漂移。
3. **数据契约边界**：`content/` 是 Python 管道与 Astro 前端之间的唯一接口，两边互不依赖对方实现。
4. **匿名设备标识**：砍掉登录/注册后，收藏/划线/做题记录按匿名设备 id 存 D1，无密码体系。

## 关键决策表

| 决策 | 选择 | 理由 |
|---|---|---|
| 抓取/生成层 | 保留 Python | 已验证、每天在跑，重写风险大于收益；ETL 离线批处理与 Web 在线服务各用最顺手的工具 |
| 迁移方式 | 绿场重建（D 盘独立仓库） | 用户要求，隔离性最强 |
| 用户身份 | 匿名设备标识，无账号 | 个人工具，砍掉登录后最简 |
| 样式方案 | 设计 token + 组件级 CSS，不引 Tailwind | 内容阅读站排版优先，token 更透明、延续原 `--sl-*` 思路 |

## 后果

- **好**：资产指纹/构建自动化取代手写升号；类型契约取代文档漂移；标准工具可学、可招人、可长期维护。
- **代价**：需同时维护 Python 与 TypeScript 两门语言（但边界清晰）；迁移期间原项目仍需正常跑。

## 迁移路线图（绞杀式，每阶段可构建/可验证/可回滚）

| 阶段 | 内容 | 验证门 | 风险 |
|---|---|---|---|
| 0 基线冻结 | 锁定原站行为 + 功能砍减清单 | 原站 verify 全绿 | 无 |
| 1 新骨架 + 契约 | monorepo + contracts + CI 骨架 | typecheck/lint/test 跑通 | 低 |
| 2 内容管道契约化 | Python 标准化，定义 content schema | pytest + 样例内容 | 低 |
| 3 Astro 前端重建 | 复刻核心页 + 新 UI + 动效 | 构建 + 本地预览 | 中 |
| 4 Worker API + D1 | Hono + Drizzle 建表/迁移 | 单测 + 本地 worker | 中 |
| 5 接线 + 上线切换 | 前端接 API、匿名身份、部署切域名 | 线上冒烟 | 高（唯一动线上） |
| 6 删债收尾 | 归档旧项目、精简文档 | 全量 CI 绿 | 低 |
