# ADR 0003：账号身份与匿名数据合并

日期：2026-08-14
状态：已接受，用户名密码部分已被 QQ 邮箱验证码方案取代
撤销：0002 中「砍掉账号/登录/注册/密码」的部分决策

## 背景

ADR 0002 基于当时的需求判断「个人工具，用匿名设备标识即可，不需要账号」，并显式砍掉账号体系。
随后在阶段 5 接入 API 时发现：

- 收藏 / 划线 / 每日一练记录都绑在 `owner_id` 上，匿名设备标识一旦清缓存或换设备即丢失。
- 计划中的「QQ 邮箱订阅每日时政摘要」必须有账号才能关联邮箱。
- 用户在多设备（手机 / 电脑）间切换时，匿名设备标识无法同步。

## 当前决策

- 未登录数据使用 `device:<device-id>` owner namespace，登录数据使用 `user:<user-id>`，原始 UUID 不能跨 namespace 读取、修改或转移数据。
- QQ 邮箱验证码验证成功时，在同一数据库事务中消费验证码、创建或取得账号、合并有效设备数据并创建 Session。并发重放只能有一个请求成功，不留下部分合并。
- 收藏按业务唯一键去重；练习记录冲突时保留账号侧记录；段落划线按更新时间选择较新状态，同时间由账号侧获胜，并保留空 spans tombstone。
- 旧单条划线与版本化段落状态冲突时按同一时间规则归并为版本化状态。合并完成后清理设备 namespace 中已转移的数据。
- 缺失或非法设备标识不触发合并，但不阻止合法验证码登录。
- 订阅状态只以 `subscriptions` 表为准，不再由 `users.subscribed` 维护第二份状态。

## 与 0002 的关系

0002 关于 admin、地区偏好和间隔重复的范围决策仍然有效。邮箱订阅已被当前 MVP 范围重新纳入。
登录方式、Session 和邮箱规则以 `docs/product/`、`docs/architecture/` 和 TASK-0004/0005 为准。

## 安全约束

- 账号认证只接受 QQ 邮箱验证码和安全 Session Cookie，不接受用户名密码或 Bearer JWT。
- `AUTH_SECRET` 未配置时，认证和需要签名能力的订阅操作不可用。
- owner namespace 是授权边界，不能把客户端提供的裸用户 UUID 解释为账号所有权。
- 验证码消费、账号合并和 Session 创建必须保持原子性。
