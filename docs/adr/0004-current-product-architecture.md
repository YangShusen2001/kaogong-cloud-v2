# ADR 0004：当前产品和目标架构

- **状态**：已接受
- **日期**：2026-08-14

## 背景

早期 ADR 将项目定位为匿名个人工具，之后又加入用户名密码账号。当前产品目标已明确为面向公务员考生的正式时政学习网站，需要 QQ 邮箱登录、跨设备学习数据、AI 原文标注和每日摘要订阅。

当前没有真实生产用户，因此不需要保留用户名密码登录兼容层。

## 决策

### 系统形态

继续使用模块化单体和清晰部署边界：

```text
Python Pipeline -> content JSON -> Astro Pages
Browser -> Hono Worker -> D1
Subscription task -> Mail Provider
```

当前不拆微服务。

### 用户身份

- 只允许 QQ 邮箱验证码注册或登录。
- 首次验证成功自动创建用户。
- 浏览器会话使用安全 Session Cookie。
- 用户名密码和 localStorage JWT 不再作为目标方案。

### 内容和 AI

- 首页显示标题、来源、分类和 80-120 字 AI 概括。
- 阅读页保留原文、发布时间、来源和官方原文链接。
- 阅读页提供原文模式和 AI 标注模式。
- AI 标注包含观点句、申论考点和政策术语。
- AI 返回结构化数据，不生成 HTML。
- AI 处理失败时降级发布原文。

### 标注所有权

- AI 标注属于文章内容，只读，随内容 JSON 发布。
- 用户标注属于用户数据，通过 API 写入 D1。
- 两类标注分开存储、渲染和删除。

### 邮件

- 验证码邮件属于事务邮件。
- 每日摘要只发送给已验证且主动订阅的用户。
- 邮件供应商通过抽象接口接入，投递必须幂等、可重试、可退订和可追踪。

## 后果

- 现有用户名密码代码需要由任务 `0004-qq-email-auth.md` 替换，不保留无实际用户需求的兼容分支。
- 内容契约必须先于 Pipeline 和阅读页并行开发。
- 内容发布增加 Schema、AI 长度、标注定位和来源完整性质量门禁。
- 邮件投递需要选定支持事务邮件和订阅邮件的供应商。
